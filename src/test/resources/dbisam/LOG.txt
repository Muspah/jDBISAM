FOUTMELDINGEN (exact) en wat ik daarna deed
---------------------------------------------
1. INSERT met datumliterals in de vorm DATE '2024-02-29':
   "DBISAM Engine Error # 11949 SQL parsing error - Expected ) but instead
    found '2024-02-29' in INSERT SQL statement at line 1, column 325"
   -> opgelost: datums/tijden als gewone string '2024-02-29' enz.

2. INSERT met bytes als string 'ABCDEFGH' in een Bytes-veld:
   "DBISAM Engine Error # 11949 SQL parsing error - Expected NULL, Bytes, or
    VarBytes expression but instead found 'ABCDEFGH' in INSERT SQL statement
    at line 1, column 285"
   -> opgelost met CAST('ABCDEFGH' AS BYTES(8)) / CAST(... AS VARBYTES(16)).

3. INSERT met hex-literal X'4142434445464748':
   "DBISAM Engine Error # 11949 SQL parsing error - Expected ) but instead
    found '4142434445464748' in INSERT SQL statement at line 1, column 286"
   -> niet ondersteund; CAST gebruikt (zie 2).

4. Alter Table op alltypes terwijl het SQL-venster nog open stond:
   "DBISAM Engine Error # 11013 Access denied to table or backup file 'alltypes'"
   -> SQL-venster gesloten, Alter Table opnieuw: gelukt.

5. CREATE TABLE "enc_all" (...) ENCRYPTED WITH 'Test1234':
   "DBISAM Engine Error # 11949 SQL parsing error - Expected end of statement
    but instead found ENCRYPTED in CREATE TABLE SQL statement at line 23, column 3"
   -> tabel zonder versleuteling gemaakt en daarna versleuteld via
      Utilities > Alter Table (Encrypted + Password).

6. Controle-query met LENGTH("f_blob"):
   "DBISAM Engine Error # 11949 SQL parsing error - Expected NULL, Memo
    expression but instead found "f_blob" in SELECT SQL statement at line 1,
    column 43"
   -> alleen een controle-query; vervangen door ("f_blob" IS NULL).

GEDRAG VAN DBISAM DAT AFWIJKT VAN WAT IS INGEVOERD (belangrijk voor de lezer)
---------------------------------------------
a. Lege tekst '' wordt als NULL opgeslagen. Geldt voor String, FixedChar,
   Memo, Bytes en VarBytes (alltypes rij 4: "IS NULL" gaf True voor alle vijf).
   Een "lege tekst die niet NULL is" kon ik dus niet maken.
b. Spaties aan het eind van een String worden afgeknipt:
   'spaties   ' (10 tekens) werd 'spaties' (LENGTH 7). In het .dat-bestand
   staat 73 70 61 74 69 65 73 00 20 20: NUL na 'spaties', daarna nog 2
   restspaties.
c. AutoInc wordt altijd automatisch gevuld (1..5), ook in de "alles NULL"-rij 2.
d. BCD: Utility toont alleen Size = 2 (schaal). Precisie (10 in de SQL) wordt
   niet getoond.
e. Datum 0001-01-01 en 9999-12-31 werden zonder fout geaccepteerd.
f. Alter Table, Optimize en Repair laten reservekopieën achter
   (*.dbk, *.ibk, *.bbk) in C:\jdbisam-testdata. Die heb ik laten staan.
